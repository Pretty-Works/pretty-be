**한 줄** — 배포 파이프라인을 금융망 규제 안에서 자동화하는 난제를 푸는 사람.

**배경** — 다온뱅크 인프라팀에서 배포 자동화를 시도하다가 2022년 3월 전출조로 합류했다. 금융권 특유의 통제(CAB 승인, 평일 오전 배포 금지 등, 00번 §7) 안에서도 자동화 범위를 조금씩 넓혀온 게 그의 경력이다.

**성격** — 장애가 나면 원인을 찾을 때까지 다른 일을 손에 못 잡는다. API 게이트웨이 장애(05번 §3.3) 때도 원인 분석을 직접 끝까지 팠다.

**업무 스타일** — CI/CD·클라우드·SRE 세 파트 사이에서 배포 표준을 통일하려 한다. 화·목 21시 '창구'(00번 §12) 배포마다 최종 점검을 직접 한다.

**강점 / 약점** — 강점은 규제와 자동화 사이 균형을 찾는 감각. 약점은 창구 배포일마다 늦게까지 남아 있어야 해서 팀 전체의 야근이 그를 중심으로 반복된다는 것.

**사람 관계** — 하수민 기술인프라본부장에게 배포 안정성을 직접 보고한다. 진병호 Infra팀장과는 장애 대응에서 손발이 맞는다. 개발본부 팀장들과는 배포 일정 조율로 종종 부딪힌다.

**지금 맡은 일** — API 게이트웨이 장애(05번 §3.3) 재발 방지 작업, 배포 파이프라인 표준화.

**PrettyWorks** — 장애 대응 할 일을 프로젝트 형태로 만들어 사후 분석까지 남긴다. 창구 배포 당일엔 알림을 가장 예민하게 확인한다.

**자주 하는 말** — "원인부터 찾고요." / "이번 창구에 태울게요."
