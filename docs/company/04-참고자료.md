# 참고자료

> 다온테크(주)는 가상의 회사다. 다만 모든 수치는 실제 기업의 공개 데이터에서 출발했다.
> 이 문서는 어떤 실측치를 어떻게 변형했는지 남긴다. 발표 때 "왜 이 숫자냐"는 질문에 답하는 근거다.

**환산계수 0.66을 쓴 이유.** 지표마다 다른 배율을 쓰면 "고객은 많은데 예금은 적은" 식으로 서로 어긋난다. 하나의 계수를 전 지표에 적용하면 1인당 생산성·고객당 수신액 같은 파생 지표까지 실제와 같은 비율로 유지된다.

**그룹 구조.** 비바리퍼블리카(플랫폼) 아래 토스뱅크·토스증권·토스페이먼츠·토스인슈어런스가 붙는 구조를 그대로 옮겼다. 금산분리 규제상 인터넷전문은행이 금융지주를 세울 수 없어 실제로도 이 형태다.

## 3. 조직문화 설정의 원본 — 토스팀

| 요소 | 실제 | 다온테크 적용 |
|---|---|---|
| DRI (Directly Responsible Individual) | 안건마다 최종 의사결정자 1명. 결재가 아니라 이해관계자 동의로 실행 | 그대로 도입. 핵심가치 2번 |
| 정보 공유 | 정보 독점이 권력이 되지 않도록 전사 공개 원칙 | 인사·재무·보안 등급만 예외로 두고 도입 |
| 무직급 | 직위 없이 '역할'만. 전원 이름 호칭 | **부분 도입.** 호칭만 수평화하고 직급 7단계는 유지 |
| 사일로 / 챕터 | 4~8명 제품 조직 + 직군별 느슨한 커뮤니티 | 파트(3~12명) 단위로 변형. 챕터는 도입하지 않음 |

출처: [토스피드 — 서버 챕터 FAQ](https://toss.im/tossfeed/article/toss-serverchapter-faq10), [아산 기업가정신 리뷰 — 토스, 금융혁신에서 조직혁신으로](https://asan-aer.org/%ED%86%A0%EC%8A%A4toss-%EA%B8%88%EC%9C%B5%ED%98%81%EC%8B%A0%EC%97%90%EC%84%9C-%EC%A1%B0%EC%A7%81%ED%98%81%EC%8B%A0%EC%9C%BC%EB%A1%9C-%EB%B9%84%EB%B0%94%EB%A6%AC%ED%8D%BC%EB%B8%94%EB%A6%AC/), [사례뉴스 — 토스의 DRI](http://www.casenews.co.kr/news/articleView.html?idxno=13835)

**무직급을 그대로 못 쓴 이유.** 금융 IT 자회사는 감독당국 제출 서류, 대외 계약, 프로젝트 투입 등급 산정에 직급이 필요하다. 또한 우리 DB의 `PositionType` 이 7단계로 정의돼 있고 권한 판정(`level`)에 쓰인다. 그래서 "직급은 남기되 호칭은 수평" 이라는 절충안을 회사 설정 자체에 녹였다.

## 4. 스키마 제약이 설정에 미친 영향

가상 회사의 형태는 상당 부분 우리 DB가 결정했다.

| 스키마 | 설정에 준 제약 |
|---|---|
| `DepartmentType` 14종 | 부서를 14개로 고정. 컨설팅·PM·QA·FE가 있다는 것 자체가 "은행이 아니라 IT 서비스 회사"를 뜻했다 |
| `PositionType` 7종 | 사원·선임 2단계 직급 + 파트장·팀장·임원·부사장·사장 5단계 보직 구조로 해석 |
| `users` 에 본부/팀 컬럼 없음 | 본부장 4명과 CISO를 각자 대표 부서에 흡수시켜야 500명이 정확히 떨어졌다 |
| `employee_no` UNIQUE, 로그인 ID | 부서 코드를 사번에 넣지 않기로 결정 (부서 이동 시 사번이 바뀌면 안 되므로) |
| `email` UNIQUE | 500명 전원 고유 이름 사용 (동명이인 금지) |

## 5. 그 외 참고

- 성씨 분포: 통계청 인구주택총조사 기준 (김 21.5%, 이 14.7%, 박 8.4%, 최 4.7%, 정 4.3%)
- 로마자 표기: 국어의 로마자 표기법 (문화체육관광부 고시)
- CISO 겸직 제한: 전자금융거래법 제21조의2 및 전자금융감독규정
- 평가 등급 분포 S/A/B/C/D = 10/25/50/12/3%: 국내 대기업 상대평가 관행
